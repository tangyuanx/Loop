# 执行阶段6：设置、恢复与系统反馈

先读`COMMON.md`、共享状态/决策、`handoffs/STAGE-05.md`和路线图阶段6，运行`node tools/frontend-remediation.cjs check 6`。本阶段的恢复、覆盖和安装行为只在受保护副本中演练。

## 目标

统一设置和重要状态的表达，让错误/恢复/权限动作可靠可理解。

## 必须完成

1. 整理外观、任务与浮窗、数据、更新、高级、帮助六类设置，统一标签、描述、控件和即时生效方式。
2. 覆盖最近删除、影响预览、恢复冲突、永久删除、撤销、备份/导入，保留原事务及回滚保护。
3. 整理更新检查/下载/准备/安装/失败/不支持，以及提醒/权限/能力检查状态，不伪造开发模式的系统能力。
4. 整理手册、帮助搜索和反馈表单的校验、提交中/成功/失败；保留必要同意和真实服务状态。
5. 对照阶段0浮层清单，补齐尚未覆盖的菜单/对话框：位置、遮挡、外部点击、Esc、焦点约束与返回。不要清空前面页面的反馈实现。
6. 重要失败/冲突/可撤销动作不套用2.5秒自熄；输入继续遵守中性、透明与明暗规则。

## 代码重点

`settings.*`、`recovery26.*`、`manual27.*`、`help.css`、`desktop.js`、`actions.js`及更新/提醒/备份/反馈桥接。反馈服务和数据协议默认不重写。

## 验收与交接

- 偏好在各入口一致；恢复失败原数据与Recovery仍在；替换/永久删除/覆盖影响明确；错误可纠正、关键反馈不会过早消失。
- 参考data-continuity/updater/deadline-reminders/notification-capability、反馈客户端/服务及最近删除回归；完整检查、空白检查。
- 启动真实Electron明暗候选，真实权限或安装未演练的场景准确登记，不能写成已验收。
- 写`handoffs/STAGE-06.md`与状态/决策，不提交或发布。

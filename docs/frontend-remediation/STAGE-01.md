# 执行阶段1：全局基础与公共控件

在固定工作区接续阶段0。先读`COMMON.md`、`state.json`、`DECISIONS.md`、`handoffs/STAGE-00.md`与路线图阶段1，运行`node tools/frontend-remediation.cjs check 1`。只做本阶段。

## 阶段0交接的具体承接

- 读取`BASELINE-STAGE-00.md`，核对当前分支、版本、依赖运行时与已保留的watcher补偿和用例；保持旧编辑器归档及候选原件，不重新整理基线。
- 阶段0实际发现搜索父`.list-search:focus-within`在明暗主题仍有绿色边线与聚焦底色变化。把这项作为本阶段明确修复和回归项，同时检查全部输入类别与父容器，不能只改搜索。
- 按基线登记的8个候选文件职责迁入公共基础；预览文字、临时主题按钮、合成数据和启动辅助不进入产品。复用隔离数据种子时新建本阶段profile，不覆盖已打开的阶段0profile。

## 目标

让主窗口、今日浮窗和独立辅助窗口共享可靠的视觉与输入基础，解决历史覆盖引起的反复偏差。沿用登记分支及前阶段文件，不初始化新应用。

## 必须完成

1. 盘点三个HTML入口的加载顺序和样式归属，为主题/字体/控件/焦点/反馈/动效建立唯一来源；记录迁移映射，不再增加一组phase补丁。
2. 按候选最后一轮反馈迁入设计规则：无绿色焦点或突出外扩环；原位编辑完全透明，只有所在项目底色与文字选区；普通表单保留细线；搜索内部透明、微色阶稳定；明暗都成立。
3. 保留字体/字号偏好，核对普通文字400/360、标题500/460的真实显示、数字等宽与行内图标；第三方编辑器单独核对，不机械套全部规则。
4. 统一按钮、图标按钮、下拉、分段控件、菜单和可操作反馈，覆盖默认/悬停/聚焦/禁用/加载/错误。错误/冲突/撤销提示不能按普通成功提示自熄。
5. 将公共规则接入三个真实入口，尤其检查浮窗输入和外层focus-within。保留原生控件语义、FormData、IME、Tab、Enter/Esc和减少动态效果。
6. 为后续阶段记录样式所有者、控件用法、例外和已迁移/仍待迁移区域；不在本阶段重新布局各业务页面。

## 代码重点

三个renderer HTML，`shell.css`、`fonts.css`、`type-readability.*`、`controls22.*`、`bridge.css`；候选`quiet-surface.css`/`neutral-inputs.css`只作受控迁入参考。改动共享字段时核对知识编辑器、任务改名与浮窗，不只检查搜索框。

# 执行阶段8：整体收敛、远端整合与最终验收

先读`COMMON.md`、共享状态/决策、阶段0–7交接和路线图阶段8，运行`node tools/frontend-remediation.cjs check 8`。所有成果已累积在同一分支，不从各会话重新收集或覆盖代码。

## 目标

形成一个可最终验收和发布的累计候选。本阶段仍不提交、升版本、打标签或推送。

## 必须完成

1. 逐项核对全项目覆盖矩阵与各阶段未解决/未验证项，修复实际阻断问题，不扩大为新功能。
2. 按已迁移区域收敛临时CSS、重复token、事件和render包装；保留已实现的DOM/编辑器复用。按真实HTML/动态/构建/导出引用判断可清理资源，不篡改历史冻结样本。
3. 核对明暗、所有输入与外层、原位透明、搜索稳定、字体缩放、键盘/屏幕阅读、减少动效、长内容/大树/长笔记和多窗口性能。
4. fetch最新main/tags，比较自阶段0以来远端变化，在同一工作区安全整合，保护所有阶段累计改动。更新后重新运行受影响检查与预览；实质代码变化会使旧验收过期。
5. 记录已经包含的origin/main commit到`state.release.remoteIntegratedCommit`。若main被其他worktree占用，核对并说明现场，不能删除或重置其他会话工作区来占用它；不要凭固定Git命令冒险。
6. 运行完整检查、相关UI组合、Mac/Windows本地包和资源校验。按项目维护技能的权限/构建要求执行。版本仍沿用基线，最终版本在发布入口一次选择。
7. 建立最终产品指纹：`node tools/frontend-remediation.cjs fingerprint`，保存JSON和包内源码对应证据。记录平台限制与真实未测项。
8. 从同一工作区启动最终真实Electron或必要本地安装包供用户审阅。等待对这一累计候选的真实反馈；继续修正则更新指纹和证据。

## 最终验收记录

只有用户明确验收实际累计候选时，才在`state.release.finalAcceptance`写入：`approved:true`、`productFingerprint`、`approvalQuote`、`recordedAt`。不能因为测试通过或进入阶段8就填批准。需要发布的明确指令另见`RELEASE.md`。

产品指纹忽略package/package-lock的根版本字段，便于最终只调整发布版本；其他源代码、依赖或构建支持文件变化仍会改变指纹。文档/状态/日志不在产品指纹内。它辅助发现变化，不代替真实检查或用户授权。

## 交接

写`handoffs/STAGE-08.md`，附全阶段覆盖、远端整合、指纹、检查/构建、最终实例和未测项。阶段达到可审阅状态可记ready_for_review；用户最终确认后再如实登记。清空activeStage，停在最终候选，不自动执行发布入口。

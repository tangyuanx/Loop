# Loop 前端整改分析与分阶段路线图

分析日期：2026-10-26。用途：作为后续逐阶段实施、启动真实实例和验收的依据。本次只形成分析与计划，不修改应用、不提交或发布。

执行机制补充：用户随后指定不同会话在同一工作区依次完成、最后统一一个版本推送。对应[多会话执行包](../frontend-remediation/README.md)及阶段0–8脚本已经建立；以下阶段范围不变，工作区与发布策略按执行包和用户最新要求执行。

## 1. 结论与基线

建议采用“先统一基础规则，再按完整使用流程迁移，最后收敛历史实现”的方式。保留 Electron、现有数据模型和真实交互，不以更换框架或重写全部界面作为起点。视觉整改与必要的局部代码整理同步进行，每阶段都应得到可操作、可独立审阅的真实应用。

当前存在三份必须区分的代码：

| 代码位置 | 当前状态 | 在整改中的用途 |
| --- | --- | --- |
| 本地 `main` / `origin/main` | 本轮 fetch 后均为 `482912b76c8666af849bbbdfd2ea806ba87bbaa4`，包版本0.1.245 | 正式功能与兼容基线 |
| 仓库根工作区 | 位于 `codex/preserved-main-20261024`，HEAD为`4a16c1b`，保留多项旧编辑器和界面未提交改动 | 保留、逐项核对；不能直接当作最新主分支实施整改 |
| `.local-review/microcontrast-20261026/source` | 从最新main完整归档，增加本轮主界面视觉、输入和折叠反馈候选 | 提取已有设计成果；不把候选直接覆盖到正式代码 |

最新候选已经过用户多轮反馈，但尚未获得“整体集成正式应用”或发布授权。当前新实例使用独立演示数据目录；现有实例和用户编辑状态应继续保留。

本报告涉及的`app/`、`tests/`和`tools/`路径，除明确注明候选外，均指上述main基线中的文件。不能用根目录旧HEAD中的同名文件替代核对。

## 2. 当前项目结构

### 2.1 前端不是单一页面

| 入口/区域 | 当前实现与能力 | 整改意义 |
| --- | --- | --- |
| 主窗口 `app/renderer/index.html` | 正式加载29份CSS、28个script；候选为31份CSS、29个script | 主界面改色不代表其他原生窗口已同步 |
| 今日浮窗 `today-widget.html` | 9份CSS；独立任务/速记、改名、排序、置顶、穿透、窗口几何 | 需落实相同基础规则，并单独验收窗口交互 |
| 浮窗辅助窗口 `widget-surface.html` | 8份CSS；设置、行菜单、速记升级、删除确认 | 是独立BrowserWindow，涉及跨窗口定位、关闭与主题同步 |
| 主进程 `app/main/` | 窗口、存储、文件、Recovery、提醒、更新、导出、指针连续性 | 是前端行为边界，不能在视觉改造中绕开 |
| 反馈服务 `services/bug-report/` | 接收主动提交的反馈，连接问题记录 | 本轮只整改表单与反馈呈现，不重写服务端协议 |
| `tools/`、`build/`、工作流 | 编辑器构建、离线导出资源、双平台打包、升级与发布校验 | 生成物不可手工修补；发布仍需要独立授权 |
| `prototypes/` 与旧设计档 | 含历史冻结基线、模拟Demo和实验候选 | 用于参考和追溯，不作为现有产品能力的替代证明 |

主窗口内的功能可分为：导航与任务仓库、任务工作台、真实处理树及记录、知识笔记、工作与成长导航、日历、回顾、设置、最近删除、帮助与反馈，以及遍布各处的菜单、选择器、确认和结果反馈。

### 2.2 已有模块化，但仍有集中耦合

main中的`app.js`为10,412行，包含477个具名函数声明，仍同时处理状态、查询、动作、持久化协调、渲染与部分旧模板。`actions.js`、`management24.js`、`recovery26.js`和知识工作区已承担各自职责，但仍通过共享全局状态和函数替换协同。

主入口当前加载的`scale.js`、`brief21.js`、`management24.js`、`window25.js`、`manual27.js`、`continuity28.js`会包装全局`render()`；候选又增加了`quiet-surface.js`包装。单个修改可能同时影响尺寸、简报、改名、帮助、原生标题栏和焦点恢复。

同时必须保留已经实现的能力：

- `render()`已有navigation、topbar、task-list、workspace及页签的区域复用，不能误判为所有内容每次完全重建。
- 知识编辑器有实例/DOM缓存和最多8项工作区缓存，已经保护部分选区、撤销、滚动与切换连续性。
- 保存、Recovery、外部文件监听、冲突和退出握手有独立链路；视觉状态必须准确反映它们。
- 工作导航已有本地阶段模型和双队列；浮窗通过真实主进程消息请求修改主数据。

因此，不应先全面重写状态管理；应在每个页面迁移时明确该页面的渲染、绑定和清理入口，逐步减少隐式包装，保住现有复用和可靠性。

### 2.3 反复出现界面问题的结构原因

| 观察到的事实 | 后续风险 | 处理位置 |
| --- | --- | --- |
| 冻结样式、阶段样式、`bridge.css`、字体修正与候选层串联加载 | 修复一处后被另一层覆盖；明暗和默认/聚焦结果不同 | 阶段1建立归属，阶段2–7逐区域迁移，阶段8清理 |
| 通用输入、原位编辑、父容器焦点、文字选区原来各自加效果 | 重复边框、第三块输入背景、绿色焦点回流 | 阶段1全入口统一，后续阶段验证具体控件 |
| 新视觉/中性输入仅由主入口加载 | 浮窗及辅助窗口继续沿用旧焦点与字体状态 | 阶段1先覆盖硬规则，阶段7完成独立窗口设计 |
| 多处全局事件与render包装 | 重复绑定、弹层未关闭、焦点跳动、草稿在切换时处理错误 | 随页面迁移收口生命周期，阶段8整体验证 |
| 最新候选为Grid过渡保留折叠分支DOM | 大量节点时可能增加隐藏DOM和遍历成本 | 阶段3建立数据规模基准并验证 |
| 保存成功、草稿已保留、文件同步失败等状态不同 | 只做视觉统一容易误报成功，或隐藏重要恢复动作 | 阶段4、6按真实状态验证 |
| 历史文件与新实现并存 | 按文件名误删仍被构建/导出/兼容链路使用的资源 | 阶段0登记，阶段8按真实引用清理 |

以上是源码事实与整改风险分析，不等同于已经证明所有风险都能在用户数据中复现。

## 3. 所有阶段遵守的界面契约

这些来自用户明确反馈，不能在后续阶段重新回退：

1. 所有输入及外层容器在默认、悬停、聚焦、键盘聚焦和编辑时均不得出现绿色边框、outline、外圈或光晕；也不恢复突出的中性外扩环。
2. 原位标题、任务行、节点、分组、简报、记录与单元格编辑不增加独立背景层。任务选中底色与文字选区负责区分，保留可辨认的中性细底线等焦点反馈。
3. 搜索内部输入透明，外层使用稳定微色阶。浅深主题都核对相邻背景，避免聚焦时跳成另一块明显底色。
4. 非纯黑暗色，正文和普通输入以400/360为当前候选基准，标题以500/460为基准。保留用户字体和字号选择；实际字重需结合字库支持核对，不能只看CSS数值。
5. 数字使用等宽特性；正文换行、长中文与英文路径可读；行内图标核对基线。不要给本来由flex居中的图标机械叠加偏移。
6. 动效解释状态，支持减少动态效果。纯成功提示可2.5秒自熄；失败、冲突、可撤销或需要操作的反馈不能统一按2.5秒隐藏。
7. 真实父子关系、折叠、拖动、任务范围和保存语义保持不变。不要用模拟树或虚构数据模型替换当前功能。
8. 本项目没有对应AI聊天流，本轮不为展示打字特效增加AI消息、点赞或云端功能。

候选已验证原位名称等文字选区为中性；表格编辑器内部选择仍有原生蓝色。本报告不宣称所有第三方编辑器内部选择已统一，后续在知识阶段按实际编辑器处理。

## 4. 阶段总览

建议“阶段0准备＋阶段1–8整改”，按下表顺序推进。每阶段通过本地真实实例验收后，再进入下一阶段。

| 阶段 | 交付主题 | 核心成果 | 依赖/主要风险 |
| --- | --- | --- | --- |
| 0 | 基线与整改边界 | 可复现的最新基线、候选差异清单、功能/状态清单和数据副本策略 | 所有阶段的前提；防止混入旧工作区改动 |
| 1 | 全局基础与公共控件 | 三个入口一致的主题、字体、输入、按钮、菜单、焦点和反馈规则 | 先落实用户硬规则；处理样式覆盖与跨窗口差异 |
| 2 | 导航与任务仓库 | 主窗口外壳、今日/仓库/分组、搜索、筛选、批量和任务管理 | 基于1；高频操作与筛选范围不能改变 |
| 3 | 任务工作台与处理流 | 标题/简报/历史、真实树、记录面板、折叠拖动与连续性 | 基于2；树关系、编辑保存和大树性能风险高 |
| 4 | 知识工作区 | 阅读/编辑/源码、查找/表格/图片/链接、文件状态和导出呈现 | 基于1–3；数据与编辑器状态风险最高 |
| 5 | 工作导航、日历与回顾 | 时间胶囊和详情、双队列呈现、截止日历、回顾筛选与返回 | 基于2–3；时间和任务范围语义保持一致 |
| 6 | 设置、恢复与系统反馈 | 六类设置、最近删除、帮助/反馈、提醒、更新和备份状态 | 基于1及相关页面；不能弱化重要数据状态 |
| 7 | 今日浮窗与辅助窗口 | 任务/速记、改名/输入、跨窗菜单、置顶/穿透/几何 | 基于1、2、6；真实多窗口与平台行为 |
| 8 | 整体收敛与发布前验收 | 历史覆盖清理、无障碍/缩放/性能、双平台包和文档一致性 | 各功能阶段完成；发布另行授权 |

阶段1之后有些页面可独立开发，但建议继续逐阶段审阅，避免同时引入多个未确认的视觉和交互方向。

## 5. 每阶段实施与验收

### 阶段0：基线与整改边界

**工作**

- 在当前固定工作区安全对齐最新main基线，保存根工作区原有修改与其他候选，确定一条后续会话共同沿用的整改分支；不重置、不打包混合代码。之后各阶段不另建worktree或孤立源码副本。
- 登记当前候选8个产品/测试差异文件，区分配色、输入、预览控件、Grid动画、提示时长与测试顺序变动；逐项决定迁入内容。
- 标注预览专属内容：设计预览文字、临时主题按钮、演示任务和启动辅助不应不加判断地进入正式产品。
- 建立三入口与页面/浮层/状态清单，准备空数据、正常任务、长标题、多分组、多层树、长笔记和异常状态的隔离数据。
- 对已存在UI专项脚本和历史测试分类，记录同一机器的切换、输入、搜索、折叠与滚动基准。

**验收**：明确基线commit和修改范围；应用在隔离目录可启动；原正式数据与旧工作区未被覆盖；确认本次主界面候选哪些部分进入后续阶段。

### 阶段1：全局基础与公共控件

**工作**

- 建立唯一的语义色、文字层级、间距、焦点、反馈与动效定义，明确各表面的样式所有者。
- 将基础定义与输入硬规则接入主窗口、今日浮窗和辅助窗口。不能把禁止绿色输入和原位透明规则拖到阶段7才覆盖。
- 区分普通表单、搜索、原位编辑、正文画布、表格单元格；公共层不为每种输入强加同一矩形背景。
- 统一按钮、图标按钮、分段控件、下拉、弹出菜单、工具提示、状态反馈和禁用/加载/错误状态。
- 收口样式优先级，不以新增更高权重`!important`层作为长期方案；保留少量明确的第三方覆盖边界。

**主要代码**：三个HTML入口，`shell.css`、`fonts.css`、`type-readability.*`、`controls22.*`、`bridge.css`；参考候选`quiet-surface.css`、`neutral-inputs.css`，按职责迁入公共层。

**验收**：同类控件在三入口、浅深主题下表现一致；默认/悬停/鼠标与键盘聚焦/外层`focus-within`均符合契约；普通输入、搜索、标题改名、正文与表格逐类覆盖；中文输入、Tab/Shift+Tab、Enter/Esc和禁用状态可用。

### 阶段2：导航与任务仓库

**工作**

- 整理原生标题栏、导航、分组、任务列表的几何与层次，保持任务内容的阅读优先级。
- 完整覆盖今日、仓库、分组、未分组、全部/未完成/已完成、速记过滤，以及窄窗与折叠导航。
- 整理搜索结果、空搜索、无匹配、筛选摘要和清除入口；明确当前范围，保留从日历/回顾进入后的返回关系。
- 统一新增、改名、分组整理、任务移动、排序、优先级/日期/循环入口，以及批量选择、结果和撤销。
- 在该模块收口重复渲染/绑定入口，保留原数据操作；同步核对原生标题栏颜色和可拖动区域。

**主要代码**：`shell.js`、`actions.js`、`bulk.js`、`management24.js`、`window25.*`、`app.js`相关查询/动作，以及仓库、时间、批量样式。

**验收**：清除附加筛选不丢失今日/分组范围；任务与速记不混淆；长标题不撑宽；新建、改名、排序、批量、撤销和快捷键保持可用；Mac/Windows原生窗口按钮和拖动区域不被遮挡。

**相关检查**：`product-experience.ui.cjs`、`group-context-menu.ui.cjs`、`context-create.ui.cjs`、`window25-renderer.test.cjs`。

### 阶段3：任务工作台与真实处理流

**工作**

- 统一标题、属性、简报、页签、历史、保存回执和任务完成后的反馈；原位编辑不新增背景层。
- 保留任意真实父子关系，整理树线、缩进、状态、操作显隐、长标题和定位，不通过平面假数据替换树。
- 完整覆盖根/子/同级新增、改名、折叠/展开、隐藏完成节点但保留未完成后代、下一待处理、右键、删除与撤销。
- 整理节点记录的侧面板、窄窗抽屉和阅读状态；验证焦点返回、滚动记忆和操作连续性。
- 将已确认的Grid过渡接入既有生命周期；评估候选保留关闭子树DOM的代价，避免为动画破坏大树使用。拖动继续复用原长按、非法目标保护和键盘能力。

**主要代码**：`workspace.js`、`brief21.*`、`flow.css`、`actions.js`、`app.js`树与记录相关部分、`continuity28.js`，以及现有指针适配契约。

**验收**：深层与跨层移动不改错parentId/order；完成父节点下的未完成后代仍可到达；折叠后隐藏内容不可误聚焦；中英文长标题、IME编辑、Enter/Esc、切换时未保存内容和焦点返回正常；对大树建立前后同条件性能比较。

**相关检查**：`node-interactions.ui.cjs`、`node-context-menu.ui.cjs`、`flow-completed-filter.ui.cjs`、`continuity28.ui.cjs`、`pointer-continuity.test.cjs`。

**边界**：不自动引入`prototypes/node-results-20261025`中的新结论字段、结论列或逐层模式。这些涉及另一个产品设计决策，需单独授权。

### 阶段4：知识工作区

此阶段建议分三个验收点，完成后仍作为一个功能阶段收口：工作区与排版 → 复杂编辑控件 → 文件/保存/导出状态。

**工作**

- 统一页签、工具栏、模式切换、专注状态、笔记切换、宽度、目录/反向链接和底部回执。
- 整理编辑、阅读、源码三种模式的文字、选区、代码块、表格、图片、公式、列表、引用、内部/外部链接和查找/替换；核对第三方内部选择与主题差异。
- 避免因工具栏或容器调整重建编辑器，保留选区、撤销栈、光标、滚动与输入法会话。
- 准确区分“保存到Loop”“草稿已保留”“文件已保存”“文件未同步”“只读/丢失/外部改动”等状态。
- 保留恢复草稿、重读、覆盖、另存、附件暂存与退出握手；导出Markdown/HTML/PDF的阅读排版单独核对，不把应用暗色直接套到打印输出。

**主要代码**：`knowledge-workspace.js`、`workbench.*`、`knowledge.js`、`knowledge-editor.entry.js`、`knowledge-editor.css`、`knowledge-core.js`、`knowledge-search.js`、`knowledge-renderer.js`、`knowledge-document.js`、`knowledge-recovery.js`及主进程知识服务边界。

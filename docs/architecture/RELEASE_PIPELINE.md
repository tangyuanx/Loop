# 发布流水线

从v0.1.239开始，主分支与PR仅运行完整代码检查，v标签运行一次跨平台打包与发布。不要再添加按版本复制的发布工作流，也不要让普通build工作流同时监听v标签。

发布仍以用户验收过的候选为基础。先核对远端最新版本与代码，保留原工作区改动，完成本地检查和必要的真实桌面验收；同一候选没有产品代码变化时复用已有验收结果，不重复人工操作。维护流程要求的本地Mac/Windows预发布构建本次仍保留。

## 标签发布

1. prepare仅创建或复用当前标签的草稿版本，拒绝已正式发布的版本。版本、标签、检出的提交必须一致。
2. macOS、Windows并行运行完整检查与原生打包。macOS产出x64/arm64；Windows产出x64并验证151/152/153三个历史版本升级。
3. 两平台分别对实际app.asar执行导出10组、冲突10组、输入/保存反馈8组、搜索7组回归。任何失败均阻止该平台上传及最终发布；截图和JSON证据保留7天。
4. 更新源先在原生runner对真实文件校验SHA-512与大小。12个最终文件随后直接上传同一草稿版本，并逐项核对GitHub计算的SHA-256。
5. 仅把包含版本、提交、两类摘要、大小与小型更新源文本的校验清单交给最终任务，不再下载和重新上传整套安装包。
6. 最终任务必须同时拿到两平台清单，校验提交/版本一致、12文件完整且无额外文件、更新源SHA-512一致、全部远端文件已uploaded且大小/SHA-256匹配，才将草稿转为正式发布。

写权限仅给予标签发布中的prepare、原生上传和最终发布任务；主分支及PR保持只读。脚本禁止向已经公开的版本上传或重写文件。

## 重试与缓存

失败时草稿保持未公开，已有正式版本及更新源不变。修复测试或代码后使用新版本；仅网络故障可以重跑失败任务，已通过平台的校验清单需仍在7天保留期内。正式版本不可用该流程覆盖，发布完成后的全流程重跑会明确拒绝。

Electron/打包工具缓存按系统隔离，精确锁文件键优先、同系统旧缓存兜底；工具自行按版本选择缓存文件。历史Windows安装器独立缓存，安装及数据保留验证仍每次执行。缓存不作为候选安装包或测试通过证据。

统计耗时应区分本地准备、平台构建/验证、上传和最终发布；保留完整门禁，再用连续发布数据判断提速，不以一次网络波动承诺固定耗时。

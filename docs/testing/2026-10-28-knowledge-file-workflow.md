# 笔记独立文件流程验证 · 2026-10-28

本次以用户最新要求替代此前“本任务创建 / 其他笔记”的区分方案。沿用当前工作区和现有表格、编辑器、文件服务与设计样式。尚未提交、升版或发布。

## 实际行为

- 任务只记住上次使用的笔记；新任务沿用当前打开的笔记，不生成同名空笔记。
- 已有任务笔记保留原内容、文档身份、文件路径和恢复能力；也可以在其他任务下打开和编辑。
- 新建直接进入空白笔记并聚焦编辑器。阅读模式下新建会进入编辑模式。
- 首次手动保存打开系统保存窗口，选择文件位置；取消不丢内容。未命名笔记首次保存后显示所选文件名。
- 未保存为文件的内容继续保留为可恢复草稿，回执明确显示“尚未保存为文件”。已关联文件继续沿用现有自动同步、冲突保护和另存为机制。
- 打开按钮和 Ctrl/Cmd+O 直接选择本地 Markdown 文件；重复打开同一路径切回已有文档。
- 最近记录快速重开文件和未保存草稿。空任务不出现在笔记历史中。
- 多篇显示上方页签；只剩一篇隐藏页签。关闭只关闭页签，内容和最近记录保留。
- 打开页签、当前笔记、每个任务的上次笔记随任务数据持久化。退出重启恢复上次任务及笔记；关闭所有页签后保持空状态。

## 修复中发现并解决

1. 切换任务时原实现将当前文档强制重置为任务笔记，改为独立文档会话及每任务上次记录。
2. 重启直接恢复笔记时，编辑器可能早于工作区回调注册而挂载，导致一直停留“正在打开”；现在等待回调就绪后挂载，进程重启测试通过。
3. 显示来自其他任务的旧笔记时，视图定位可能误触发任务切换，导致刚关闭的页签重新打开；现在区分当前任务的会话选择与文档视图定位，表格及关闭重开回归通过。
4. 最近记录曾把空任务列为草稿，现已排除，避免再次产生强行绑定的观感。

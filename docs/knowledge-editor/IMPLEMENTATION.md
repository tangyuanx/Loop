# Loop 知识笔记升级交付与验证

基线：`ed9f3e2`，Loop v0.1.232。修改范围为现有任务下的知识笔记，保留 Electron 主进程、任务数据、分组、入口、文件权限检查、附件、恢复和导出边界。

## 检查结果与改造选择

原实现有三条不同的正文路径：Milkdown 富文本、textarea 源码和自定义 Markdown 阅读渲染。富文本序列化可能规范化原文，源码缺少专业编辑能力，阅读语法覆盖不足；phase23 额外包装保存状态，和实际文件回执存在多份状态。自动保存原本主要保存任务数据/恢复草稿，而非同步绑定的 Markdown 文件。附件回执还可能触发整页刷新并使输入失焦。

采用知识笔记内部重做：CodeMirror 6 保管 Markdown 原文及编辑历史；同一实例提供源码与实时预览，阅读视图使用相同文档快照。Live Preview 使用增量语法树、可见范围装饰和部件，非活动语法隐藏/渲染，光标或选区进入时恢复源码。处理流里的短记录仍使用原 Milkdown 编辑器。

运行时不再加载 `notebook23.js` 的多层保存包装，改由 `knowledge-workspace.js` 统一驱动笔记保存状态。旧文件保留供历史回归测试参考。

### 链接与历史数据

- 正文仍在 `task.notes`，归属仍是 `task.knowledgeNote.taskId`，身份仍为原 `noteId`。不新增第二个笔记库。
- 新补全链接形式为 `[[note:<noteId>|显示名称]]`，可加 `#标题` 或 `#^块ID`，重命名后身份稳定。
- 历史 `[[标题]]` 通过当前标题和持久化 `knowledgeNote.aliases` 解析。重名时要求选择，避免默默指向错误记录。
- 重命名为元数据增加旧名称别名，不批量重写其他笔记正文。文件名和任务标题由现有业务分别管理。
- 不迁移正文格式，也不删除历史文件/附件；仅增加可选别名和移除状态元数据。只有保存已暂存图片时，沿用原机制将相应图片目的地址改为附件相对地址，并映射编辑器状态；该内部事务不占用用户撤销历史。
- 移除笔记沿用最近删除，磁盘 Markdown 和附件保留。移除状态从候选与索引中排除，指向该笔记的链接会提供恢复入口。旧版本可读任务/正文；旧版本再次保存元数据可能忽略新别名，建议使用本版本完成关联笔记编辑。

## 启动

```bash
npm ci
npm run build:knowledge
npm run dev
```

构建入口 `npm run check` 和 `npm run dist` 都已包含知识笔记编辑器打包。仓库原有指向开发者绝对路径的 `node_modules` 符号链接已移除，依赖应由 `npm ci` 安装。

使用隔离配置目录检查，不影响日常数据：

```bash
# macOS/Linux
npm run dev -- --user-data-dir=/tmp/loop-knowledge-review
# Windows
npm run dev -- --user-data-dir=C:\Temp\Loop-knowledge-review
```

在任务工作台进入“知识笔记”。顶部“实时预览 / 源码 / 阅读”切换视图，放大镜搜索笔记，大纲按钮展开标题与反向链接；点击笔记名重命名。更多菜单沿用打开文件、另存为、导出和最近删除路径。

快捷键：Ctrl/Cmd+S 保存、Ctrl/Cmd+Shift+S 另存为、Ctrl/Cmd+F 查找/替换、Ctrl/Cmd+Z 撤销、Ctrl/Cmd+Shift+Z 重做、Ctrl/Cmd+B 粗体、Ctrl/Cmd+I 斜体、Ctrl/Cmd+K 插入链接、Ctrl/Cmd+E 阅读/编辑切换、Ctrl/Cmd+O 搜索/切换笔记。编辑器外仍保留 Loop 原有全局快捷键。

## 实际执行的验证

- `npm run check`：主项目 325 项测试、服务端 11 项测试全部通过，包含编译和语法检查。
- `npm run test:knowledge`：16 项关键单元/磁盘服务测试通过，已包含在主项目测试总数中。
- `npm run test:ui:knowledge`：真实 Chromium 打开 Loop 生产入口，通过隔离 IPC 测试桥调用项目原有的实际磁盘服务；不使用用户日常配置。
- 浏览器验证涵盖模式不改写、渲染、中文组合输入、撤销、替换、列表、任务、补全、表格、上传期间输入、图片粘贴/拖入/失败/重试、磁盘保存失败/重试、草稿重启、并发、冲突、新建/重命名/反向链接、最近删除恢复、安全降级、长文档以及 1024/1440 宽度的深浅色界面。
- `test:ui:product`、`test:ui:node-interactions`、`test:ui:node-menu`、`test:ui:flow-filter` 通过，确认任务列表、处理流手势/右键、记录保存、隐藏完成节点等相关行为没有回归。
- 本环境通过 `LOOP_TEST_CHROMIUM` 指定现有 Chromium；在本机可先运行 `npx playwright-core install chromium`，再运行上述 UI 脚本。

## 已实现但尚需原生平台确认

- Windows/macOS 系统输入法候选窗、系统截图剪贴板和 Finder/Explorer 拖入。Chromium 的真实 composition 会话和浏览器 paste/drop 事件已验证，不能替代两个系统上的完整手工测试。
- 用户实际设备上的 Electron 启动与升级后使用仍需验收。v0.1.233 发布流程包含两端构建、Windows 安装升级矩阵和更新元数据校验；执行结果以对应 GitHub Actions 为准。
- 快捷键代码复制使用浏览器剪贴板 API；需在原生 Electron 中确认系统授权行为。

人工检查步骤：新建测试笔记 → 输入连续中文并保持候选窗超过 2 秒 → 确认候选后混输英文/Emoji → 撤销/重做 → 粘贴系统截图并在上传时继续输入 → 切换笔记再回来 → 三种模式切换 → 在另一编辑器修改绑定文件并确认冲突提示 → 重启确认恢复草稿。

## 范围与边界

- 这是本地单实例桌面 Loop，原项目没有账号、云端工作区或多端同步接口；没有虚构服务器权限或引入云同步。其他程序对绑定文件的修改由哈希冲突检测保护。
- 块引用实现基础段落 ID（`段落 ^id`、`[[笔记#^id]]`）；嵌入限制三层并检测循环。不包含 Obsidian 的完整块管理器、所有复杂块形态或插件行为。
- 图片新上传支持 PNG/JPEG/GIF/WebP/AVIF/BMP，单张上限 20 MB；历史 SVG 以消毒后的图像形式展示。越出笔记所在目录的本地相对图片不会自动读取。
- 相对 Markdown 链接只导航到 Loop 已有真实记录或提供创建入口，不扫描磁盘生成另一套笔记记录。
- 没有实现用户已排除的主题市场、插件系统、Canvas、云同步服务及高级知识图谱。
- 没有声称与 Obsidian 所有未列明的编辑细节完全一致；移动端、屏幕阅读器、超大附件和所有第三方 Mermaid 图种未逐一人工验证。

## v0.1.233 发布检查补充

- 修复快速按 Enter 时被 CodeMirror 默认 75ms 补全保护延迟拦截的问题。
- 编辑器在独立状态字段中保留每个换行的原始写法，使用 CodeMirror 的历史效果恢复换行映射；界面和解析仍使用编辑器位置，持久化输出恢复 CRLF、CR、LF 及混合格式。
- 磁盘读取与保存保留原文，CAS 哈希覆盖实际文本，因此仅换行格式的外部变化也会触发冲突。既有 LF 文件和哈希不变。旧版本记录的 CRLF 文件哈希若因旧版规范化而不同，沿用现有文件变更处理：干净笔记重新读取，未保存草稿保留并提示冲突，绝不直接覆盖文件。
- 新增测试覆盖混合换行序列化、只改换行的磁盘冲突，以及真实 CRLF 文件的模式切换、任务勾选、保存、附件路径更新和撤销重做。
- 发布前发现并修复回顾页日期范围经过 UTC 字符串重解析后在部分时区偏移一天的问题；原有回归用例直接验证修复。

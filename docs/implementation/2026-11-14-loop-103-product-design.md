## 产品定义

同一套分享面板支持两种交付结果。给别人阅读时，默认导出 Markdown。需要对方继续处理时，导出一个 `.looptask` 文件，对方可在 Loop 中预览并导入为独立任务。完整任务、简报、处理流、单节点／子树、所选知识笔记及自定义组合都走同一套范围选择。每次只处理一项任务，发送方通过现有渠道传递文件，接收方可离线完成导入。

用户已确认两项规则。**完整任务默认包含节点记录，节点及自定义分享时手动勾选。导入保留包内截止日期，关闭提醒，重复规则由接收者重设。** 包扩展名、容量、附件类型及其他部分分享的默认值属于本次设计建议。

## 发送方流程

沿用任务「分享」、处理流右键「分享此节点…」、知识笔记「⋯」里的「导出笔记…」。分别打开「完整任务」「节点／子树」「当前笔记」预设。任务分享面板也可以切到简报、整个处理流或自定义。笔记独立导出的 HTML／PDF、任务和节点已有的 PDF 继续可选。两种主格式显示为「Markdown · 阅读」与「Loop 任务包 · 继续编辑」，默认选中 Markdown。

| 范围 | 默认选中 | 仍可调整 |
| --- | --- | --- |
| 完整任务 | 标题、优先级、状态、截止日期、简报、全部处理流和节点记录、任务主笔记、任务创建的非空笔记及显式关联的笔记 | 可去掉记录、具体笔记或截止日期。改变内容后显示实际已选范围 |
| 简报 | 任务标题、背景、进展、结论 | 可加选其他模块，切入自定义 |
| 处理流 | 所有节点，包含父子层级、相对顺序、状态、判断、结论，以及选中节点之间的下游关系 | 可切换记录和缩小节点范围。独立处理流建议默认关闭记录 |
| 节点／子树 | 当前节点、全部直接及间接子节点；下游默认关闭；记录默认关闭 | 子节点深度、下游层数独立选择。预览明确列出新增节点及其来源。深度均选 0 时只分享当前节点 |
| 知识笔记 | 从笔记入口进入时选当前文档。任务入口可多选本任务的可用笔记 | 显示任务拥有、显式关联和仅打开的笔记。后者必须逐篇勾选。资源页签和最近打开列表不会自行扩张候选范围 |
| 自定义 | 从当前入口的范围开始，记录重新默认为关闭 | 简报、处理流／节点、笔记可独立勾选。至少有一项实际内容，才可导出 |

处理流从原始树计算，折叠、搜索筛选、已完成隐藏都只影响屏幕展示。选中的子节点若没有选中祖先，提升到最近的已选祖先下或成为导入任务的根节点。省略的祖先及兄弟标题不作为占位文字写出。节点及笔记的交叉引用只在两端都选中时保留可跳转关系。仅通过双链、引用或已打开页签出现的其他笔记可提示用户显式选取，其正文不自动加入。无实际内容且无文件绑定的占位草稿无需显示在默认预选中。

面板显示本次输出的模块、节点树、记录开关、所选笔记、图片／附件数量、估算大小及需处理的问题。可展开核对将带出的内容。快照包含打开分享面板时已输入的简报、记录和所选笔记草稿，外部冲突时展示「使用当前 Loop 草稿」或「返回处理冲突」；用户改了来源内容后，可刷新快照并重新核对。切换格式共用同一份选择。取消保存保留面板配置。导出成功显示文件类型、名称和「在文件夹中显示」。

### 可读文件与可恢复文件

| 交付 | 用户收到的文件 | 使用方式 |
| --- | --- | --- |
| Markdown | 无本地资源且最多一篇笔记时，输出单个 `.md`。多篇笔记或含本地资源时，输出一个 Markdown ZIP，解开后从 `README.md` 开始阅读，笔记与附件均用相对路径 | 用普通编辑器阅读。任务摘要和处理流在入口文档，多笔记各保留正文和内部跳转。表格、代码围栏、公式及图表源码保留，具体渲染效果随阅读器 |
| Loop 任务包 | 一个 `.looptask`，包含所选任务结构、笔记 Markdown 源文、包内资源、版本和完整性信息 | 用 Loop 的「导入任务包…」打开，预览后生成一项可继续编辑的任务 |
| 现有 PDF／HTML | 保留现有入口的格式能力。所选内容或附件无法在固定版式里显示时，导出前显示具体问题，允许用户接受可读降级 | 适合阅读和存档。需要完整附件文件时可选 Markdown ZIP 或任务包 |

结构化数据采用字段白名单。任务包含可见的任务状态，以及选中的优先级和截止日期。部分分享的任务包以所选节点或笔记标题、简报标题或用户输入的标题创建任务，面板明示将携带的任务状态。截止日期和优先级建议仅在「完整任务」默认勾选，部分分享可显式带出。简报之外的部分分享无需带出源任务标题。发送方的分组、安装标识、工作导航、今日／稍后队列标记、提醒、重复规则、历史操作日志、回收站、页签布局、浏览记录和绝对路径都排除。节点记录与「历史处理」含义分开。后者在现版由节点时间派生，导入后可从所选节点重算。

正文中的本机链接单独处理。符合条件的本地资源打包并改写为包内相对引用或受管资源引用。未选中的知识笔记链接改为无跳转的标签，省略外部笔记标题或路径等未选内容。识别到正文或代码示例里的疑似本机路径时，在预览中标出位置，支持查看和选择遮盖，避免通过全局替换误改技术文档。网页链接保留可点击文字，远程图片默认转为外链，分享预览和导入预览不主动联网。

### 图片、附件与复杂笔记

- 分享范围决定资源范围。收集所选简报、节点记录、结论及知识笔记实际引用且能识别的 Loop 图片、笔记目录内图片和明确链接的普通文件。先在面板列出文件名和大小。目录、执行文件、未选文档的资源及未经授权的目录外文件均不加入。用户可通过原生文件选择器明确授权单个目录外附件。首发普通附件可覆盖 PDF、常见图片、Office 文档及文本类文件，具体类型由实现阶段验证。
- 任务包缺少必须的资源时，指出来源文档、资源名和修复方式。发送方可以重新定位文件、调整范围或显式排除该资源。显式排除后输出里有可见占位，摘要与包内容一致。可读格式在确认后可保留占位继续。接收方校验发现包中声明的内容缺失时，导入整体失败。
- 任务包用现有编辑器的 Markdown 源文作为笔记内容，只改写实际资源／文档链接与用户确认的遮盖位置。保留换行、表格、公式、图表、Front Matter 和源码片段。预览通过现有受限渲染管线，HTML 源文保持惰性。#99 完成前，复杂表格仍按现版能力阅读／编辑。将 #99 的格式样本纳入同一往返用例，再决定是否需要新增任务包能力标记。

## 接收方流程

任务仓库新增「导入任务包…」，建议放在现有新建任务相关菜单里。原生选择 `.looptask` 后，Loop 先验证结构、版本和附件完整性，再显示任务名、来源范围、节点数、记录是否包含、笔记和附件清单、预计使用空间，以及「笔记将作为 Loop 草稿导入」。选择本地分组，默认未分组，可改任务名称。预览明确提示截止时间以接收方时区显示，提醒关闭且没有重复计划。完整包的任务完成状态和任何所选节点状态原样保留。部分包仍保留打包时明示的任务状态及所选节点状态。

确认后新增一项独立任务，原任务和其他本地数据继续可用。任务、节点、笔记和资源重新分配本地 ID。接收端缺少所用的自定义节点状态时，预览展示将新增的定义，遇到重名或容量冲突时给出处理选择。重复打开同一个包可以再次创建独立副本，同一确认请求的重试只产生一份。导入成功后提供「打开任务」，即使新任务不符合当前筛选也能准确跳转。导入页签按包内笔记顺序就绪，接收方自行调整分屏。知识笔记打开即可编辑，外部 `.md` 路径留空，按保存时由接收方选路径。取消保存、关闭页签、退出和重启时保留 Loop 内的草稿及资源，沿用现有恢复与关闭反馈。首次成功另存时，笔记引用的资源一起写到同目录旁的附件位置，处理重名并保护现有文件。

| 接收状态 | 界面反馈和数据结果 |
| --- | --- |
| 正在检查或写入 | 显示当前阶段和进度。校验与暂存阶段可取消。提交期间按钮禁用并显示「正在写入」 |
| 版本太新、文件损坏或选错格式 | 给出可执行的提示，例如更新 Loop、重新取得包，或转到对应的备份入口。保留当前工作，零新增 |
| 预览后文件被替换、空间不足或写入失败 | 标明阶段，保留已选设置；按问题要求重新读取、换盘或重试。磁盘与界面均无半套任务 |
| 中断后重启 | 恢复逻辑确认提交是否已完成。已提交的任务和资源完整可用，未提交的暂存可安全清理 |

## 首发验收

1. 五种预设与自定义组合均有端到端用例。源数据包含隐藏的已完成节点、同名笔记、未选兄弟和无关页签，文件及预览均只出现所选范围。
2. 完整任务默认含记录；节点与自定义默认关闭。记录取消后其独占资源也不导出。选中未完成任务的多行结论完整保留。
3. macOS 与 Windows 双向实包往返。核对树层级、排序、状态、结论、下游关系、笔记、链接和附件。接收方任务重名可共存，原任务独立，提醒关闭、重复计划为空。
4. 新笔记及其图片／附件在导入、编辑、关闭、重启、恢复、首次保存取消与重试后可用。另存后的 Markdown 和附件可从接收方目录单独打开。
5. 损坏、新版、超限、用户取消、磁盘写入失败和进程中断有明确结果，现有数据与外部文件保持一致。预览与输出读取同一份快照。
6. 真实 Electron 在浅／深主题、最小窗口、放大字号和全键盘操作下可用。输入框及外层保持中性焦点，笔记「⋯」、页签条「+」及现有分屏交互沿用项目规范。

首发覆盖一个发送者和接收者通过文件交接的完整流程。多人协同、链接托管、覆盖或合并、批量打包／导入、系统双击文件关联和云同步可以独立排期。#38 的处理流可读输出复用本方案的选取与排版，模板能力按原条目推进。#100 的删除保留期后续沿用同一资源引用清理入口。#102 的结论显示规则与 #103 的文本保真各自验收。 [#38](https://app.notion.com/p/417481a1e6628177b0d8deb60b5115e1) · [#99](https://app.notion.com/p/417481a1e66281c7bd30ccfe9acdbf66) · [#100](https://app.notion.com/p/417481a1e662815c9725c700733ea0b0) · [#102](https://app.notion.com/p/417481a1e6628156bef8d091df034c16)

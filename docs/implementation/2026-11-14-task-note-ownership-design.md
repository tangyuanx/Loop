# 任务知识笔记归属与分享范围设计

2026-11-14 · 设计评审稿 · 基线 v0.2.33，提交 `e5caaf16`

用户在 Windows v0.2.33 分享真实任务时遇到大量「重新选择附件」提示。用户已澄清，在任务中打开另一篇笔记可能只是查阅参考，需要统一设计笔记归属与默认分享范围。

## 当前实现与已复现路径

| 当前事实 | 具体行为 |
| --- | --- |
| 仅打开笔记 | `knowledgeAttach` 更新页签和最近打开，不写任务归属。分享投影把它列为 `open`，默认不勾选 |
| 在任务中创建笔记 | 写入 `creatorTaskId`。该字段同时被分享投影解释成任务拥有 |
| 任务旧关联 | `knowledgeLinks` 中的文档默认选中，当前没有日常界面让用户明确管理它的归属含义 |
| 导入任务包 | 所选附加笔记统一分配给新任务，同时写入创建任务和旧关联 |
| 外部 Markdown 引用 | 已登记且未选中的笔记引用会转成可读文字；目标未登记的 Markdown 链接会继续按附件处理，无法取得文件时提示重新选择 |
| 首次保存目录 | 当前会从打开页签和关联笔记里寻找目录，参考笔记也可能参与目录推断 |

用生产投影和资源收集逻辑复现了三个场景。A 任务仅打开 B 的参考笔记时，B 不被默认打包且不产生附件问题。B 出现在 A 的旧关联时，它会被选中并产生其中的缺失附件提示。A 正文里的外部 Markdown 参考未登记时，该链接也会进入缺失附件清单。

这些场景说明了需要处理的路径。用户当前任务具体命中了哪条路径，仍需真实分享摘要或复现数据才能确认。

## 关系模型

一篇知识笔记保有稳定身份、正文、文件绑定和资源。任务持有显式的「本任务笔记」清单。页签记录阅读现场，正文链接记录引用。

| 关系 | 如何产生 | 完整任务默认分享 |
| --- | --- | --- |
| 本任务笔记 | 在本任务中新建，或用户点「加入本任务」 | 包含有内容的笔记及其实际资源 |
| 参考笔记 | 打开文件、最近打开、搜索、点击引用或分屏查阅 | 由用户按需选入 |
| 正文引用 | 一篇笔记或记录链接到其他笔记 | 按本次所选范围决定是否能跳转，不沿引用继续收集其他笔记 |
| 打开页签 | 打开、切换、排序和关闭 | 只影响阅读位置和显示顺序 |

建议允许同一篇笔记被多个任务明确加入。加入后各任务使用同一篇文档，编辑即时共用。用户可以在一个任务里将它改为参考，在另一个任务中继续保留归属。创建来源作为历史信息保留。

分享中的勾选仅决定这一次输出。用户需要让某篇参考笔记以后都跟随任务分享时，通过笔记菜单明确加入任务。

## 日常交互

- 在页签条最右侧点「+」或从「⋯」新建，直接创建本任务笔记。
- 「打开／最近打开」继续位于右上角「⋯」菜单，打开后作为参考使用。
- 当前笔记菜单显示关系信息。参考笔记显示「参考笔记」及已知的所属任务，提供「加入本任务」。本任务笔记提供「改为参考笔记」。
- 加入已属于其他任务的笔记时，菜单旁的说明写「与原任务共用这篇笔记」。直接记录明确的加入操作。
- 改为参考后，当前页签、正文、文件绑定和已输入草稿继续可用。关闭页签只结束当前任务的阅读位置。
- 页签条继续承载切换、拖动排序、双击改名、关闭、溢出滚动和新建。关系信息放菜单与分享设置内，避免给每个页签叠加标记。

## 分享面板

首屏继续沿用已经评审的紧凑面板。

默认摘要可以显示「任务简报 · 6 个节点（含记录） · 3 篇任务笔记」。完整任务选中实际所属的全部笔记，关闭的本任务笔记也能分享。资源从本次选中的正文产生。

展开「调整分享内容」后，笔记区域首先列出本任务笔记，默认勾选。另有一个折叠入口「额外包含参考笔记」，供用户按需选择已打开的参考文档。搜索可用于加入其他已登记的笔记，结果显示它与当前任务的关系。

临时选入一篇参考笔记后，重新计算该文档的附件。取消选入后，该文档独有的资源和问题从本次输出中一并移除。默认完整任务范围固定由显式归属计算，切换页签、打开参考资料、分屏或浏览记录不会扩大它。

## 正文链接与附件

| 内容 | 分享行为 |
| --- | --- |
| 已选任务笔记之间的链接 | 保留包内跳转 |
| 指向未选中笔记的链接，包括目标尚未登记的 Markdown 文件 | 输出可读引用文字，摘要中可查看外部参考；其文件和资源不进入附件修复清单 |
| 正文内嵌图片、Loop 管理的附件 | 随所选内容收集，按内容摘要去重 |
| 所选正文实际附带的普通文件 | 沿用现有附件范围，读取允许范围内的文件，无法取得时给出具体问题 |
| 网页与远程图片 | 沿用现有外链输出与离线预览 |
| 本机绝对路径 | 复用现有标记与用户选择的遮盖行为，分享输出避免带出未选文档的路径 |

判断参考笔记时应先识别文档语义，再进入附件收集。Markdown 文件链接不会因为未登记或文件丢失就自动变成要随任务修复的附件。正文中的代码示例与普通路径文字保留原有解析边界。

## 缺失附件反馈

首屏只显示一条汇总，例如「2 篇笔记中有 7 项附件不可用」，并提供「查看」。问题按来源笔记或节点分组，展开后再看文件名、问题原因和「重新选择」。

默认保持问题明细收起。用户可以修复文件，或明确选择「排除这些附件，保留说明」后继续。重新计算实际缺失数量，导出快照和说明保持一致。

实际正文图片或附件缺失时保留可执行反馈。参考笔记及其独有资源在未选中时不会产生这些提示。一篇参考文档里有几十张失效图片，也不会让普通任务分享出现几十个待选文件。

重新定位的绑定只在当前准备分享的快照内生效。要修复笔记本身的资源，应通过原有文件与笔记保存流程处理，并显示真实保存结果。

## 持久化与历史兼容

建议新增任务级显式清单 `knowledgeNoteIds`，以字段是否存在区分旧记录与已迁移记录。空清单表达用户已经明确移除全部归属。去重、有效身份检查和归属判断在共享模型内实现，渲染端和桌面存储使用同一规则。

- 迁移旧任务主笔记和创建来源明确的本任务笔记，延续当前默认分享。
- `creatorTaskId` 仅用于旧数据迁移和来源展示。迁移后移除笔记归属，不再被创建来源重新选回。
- 旧 `knowledgeLinks` 若只有关联而缺少明确归属来源，保留为可选参考。把来源不明的关联纳入默认范围需要用户明确加入。
- 当前及历史页签、最近打开、正文链接、文件夹路径和保存目录均不用于推断归属。
- 导入任务包时，将包内确实交付的笔记加入新任务的显式清单。重启、重试、首次保存取消和恢复均保留它。
- 恢复备份和旧版包导入走同一归属迁移。重复执行结果一致，已有显式空清单保持为空。
- 保存已绑定文件时沿用文档自身路径。新建笔记首次保存可使用本任务记住的目录；从目录候选中排除仅打开的参考笔记。
- 移除任务归属保留独立文档。任务删除与恢复需要核对共享笔记在其他任务的引用和资源，沿现有恢复机制保留可达内容。

新增清单是本稿的实现建议，需在真实候选中一并验证浏览器与桌面规范化、保存队列、任务包导入和恢复。

## 验收场景

1. A 的任务笔记与 B 的参考笔记同时打开。默认分享 A，B 的正文、路径、图片和缺失资源均不带出。
2. 关闭 A 的某篇本任务笔记后继续分享，仍包含该笔记。只打开 B 及分屏查看不改变结果。
3. 将 B 明确加入 A 后，A 的下次分享会包含它。再改为参考后，重启与刷新预览都不会自动选回。
4. 在分享设置临时选入 B，只影响本次输出。取消勾选时移除 B 独有的资源和待修复问题。
5. A 里有十个链接指向其他任务的 Markdown，其中包含未登记与已丢失文件。默认只保留引用文字，零笔记引用修复项。
6. A 自身的图片实际缺失，首屏给出一次汇总，展开可修复，明确排除后导出留有说明。
7. 两篇已选笔记引用相同附件时只打包一次，取消一篇后仍能为另一篇使用。取消全部引用来源后该资源移除。
8. 旧主笔记、任务内创建笔记、旧关联、独立打开笔记和导入笔记各有迁移样本，验证显式空清单与重复迁移。
9. 知识笔记保存、Undo、草稿、重启恢复、关闭和分屏延续真实编辑器。所有输入及父容器在明暗主题和键盘焦点下遵守中性边界要求。

先完成归属与迁移模型，再接笔记菜单和默认分享，随后补上引用分类和附件汇总。以含跨任务参考、失效 Markdown 引用及真实缺失图片的真实 Electron 候选评审，之后按项目流程验收和发布。

# 问题 #120：知识笔记编辑时页面跳动

原记录：[知识笔记中，在表格内编辑时偶现页面跳动](https://app.notion.com/p/41a481a1e662809bb664ec9ae5a27000)。

基线为远程 `main` 的 `64d414cd602e1218d918ff49a9d4ea768b0bbcd6`（v0.2.50）。工作目录原为空，已克隆此版本；所有复现使用新建 Markdown、附件和隔离 Electron profile，没有读取正式用户数据。用户随后授权发布，候选版本更新为 v0.2.51，复用本轮本地验收；正式检查、双平台实际包专项与发布门禁由发布流水线执行。

## 复现与原因

1. 在包含多组代码块、提示块的长笔记中，滚动到中段的长表格，单击正文单元格并输入。基线中一次点击令文档高度从 24340px 降到 21846px，单元格离开屏幕；随后输入又改变滚动位置。证据：`.local-review/scroll-probe-before.json`。
2. 表格装饰已覆盖整份文档，但代码块、提示块、图片和公式等装饰仍按视口前后 2000 字符反复撤换。撤换成源码会改变屏外高度，影响下方表格和普通正文。每次几何变化又派发视口刷新，进一步放大这个循环。
3. 关联问题：长表中的单元格撤销/重做会要求 CodeMirror 滚动到源码选择；整表只有一个替换组件，源码位置映射到表格边缘，实测一次撤销位移 3138.5px。历史命令会跳过 transaction filter，必须在单元格的历史命令派发处处理。

## 修改

- 影响排版的装饰在文档范围内保留，DOM 仍由 CodeMirror 虚拟化；移除由滚动/几何变化驱动的视口重建。
- 有限预算补齐语法树，并在解析树或显式块展开状态变化时更新装饰。
- 渲染缓存容量随文档行数设置，避免长笔记超过旧 160 项上限后每次输入都重新渲染全部块；保存仍刷新资源引用。
- 单元格键盘和菜单撤销/重做共用历史入口，保留完整事务效果与注解，仅移除单元格的整表滚动请求；普通正文历史、查找和大纲跳转维持原入口。
- 新增 `npm run test:ui:knowledge-scroll`，记录每帧目标坐标、滚动位置、文档高度和行高；已接入 macOS/Windows 原生 CI。覆盖长混合笔记、普通/富文本单元格、撤销重做、保存、中文输入法、非表格正文、块编辑、模式切换和明暗主题。

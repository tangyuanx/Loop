## 阶段 0 · 冻结基线、样本和数据契约

重新核对执行时的远端 `main` 与正式标签。写入前保留已有工作，特别核对知识笔记格式化改动对 `knowledge-core.js`、编辑器和导出入口的影响。本次分析以正式标签源码为准。用两个隔离的 Electron profile 建立发送方和接收方，记录源码、版本、数据目录、平台和操作入口。样本包含活跃／已完成任务，三层以上的树，隐藏节点，下游关联，同名但不同 ID 的笔记，未选笔记，共享笔记，两个同名文件，各种来源的图片／附件和既有接收方数据。用独特标记标记不应分享的字段与字节。

本次从正式标签取样运行了节点分享、知识核心、知识可靠性、知识导出、知识资源及数据连续性六组现有测试，66 项通过。该结果是源码基线证据。实施阶段补真实 Electron 和跨平台安装包证据。

阶段出口为一份受版本控制的 V1 样本、字段与引用规则、拟采用的资源存储方案，以及最小包往返记录。先证明以下三个接口能在真机闭合，再冻结格式和上限。

- 包内两个同名笔记经重映射后仍可通过稳定链接打开准确目标。
- 草稿中的二进制附件在重启后可打开，首次另存可搬迁链接和文件。
- 写入期间的旧全量快照无法覆盖导入后的任务。用可控延迟和进程中断定位提交边界。

### V1 接口建议

包扩展名 `.looptask`。ZIP 内有 `manifest.json`、`task.json`、`notes/<包内文档键>.md` 和 `assets/<摘要>.<扩展名>`。清单记录固定 `format: loop-task-share`、整数 `version: 1`、生成器版本及实际条目的类型、字节长度和 SHA-256。`task.json` 放选取范围、任务与节点白名单、笔记索引／顺序、资源引用表和实际使用的自定义状态描述。任务键、节点键、文档键、稳定笔记键与资源键分别建映射，避免把包内键直接作为本地 ID。发包时也生成独立的包内键。

| 对象 | 投影与接收方写入 |
| --- | --- |
| 任务 | 标题、状态、选中的 `priority`、`deadlineAt` 和简报字段 `description`、`hypothesis`、`conclusion`。缺少的选填字段走本地默认值。分组和任务列表顺序取接收方设置 |
| 节点 | 包内键、标题、状态、`hypothesis`、`conclusion`、显式选中的 `note`、所选节点的内容更新时间、按顺序排列的 `children` 与有效下游键。本地任务和父节点 ID 从结构生成，折叠状态由接收方产生 |
| 笔记 | 包内文档键、标题、正文条目、任务主笔记标记、选中顺序。引用表记录所属文档／字段、目标与锚点，接收方建立新的稳定链接和页签关联 |
| 资源 | 资源键、内容摘要、字节数、显示名、类型、引用它的包内所有者。相同内容可共用一个包条目，显示名、引用位置和授权范围仍逐一保留 |

校验器严格核对必需字段、数值和 UTF-8、结构约束、引用闭合、重复键、层级和顺序、条目边界及实际字节。包内状态为 `todo`、`done`、`review` 或指向包内状态定义。记录是否包含用一个显式字段表示。已知版本允许文档化的可选字段，读取仍按白名单映射。新结构或新语义需要版本升级或显式声明必需能力。碰到不支持的版本或必需能力，预览前返回升级提示。SHA-256 用于识别传输和存储损坏。导入端仍按外部输入校验。

以主进程流式 ZIP 读写为候选，读取须可按条目控制、计量实际展开字节并支持取消。`yauzl`／`yazl` 可在阶段 0 评估，冻结前检查 Electron 实际包内的生产依赖、取消和跨平台文件行为。避免把传递依赖当成发布契约。 [yauzl 项目文档](https://github.com/thejoshwolfe/yauzl) · [yazl 项目文档](https://github.com/thejoshwolfe/yazl)

建议的双平台压测起点是单包文件及展开总量各 256 MiB、单资源 32 MiB、最多 512 个资源和 1,024 个 ZIP 条目；每包最多 100 篇笔记、单篇 4 MiB、所有笔记合计 32 MiB；任务 JSON／清单各 4 MiB，最多 10,000 个节点、树深 32 层。按读取实际字节和计数执行同一套导出／导入限额。用普通包（约 25 MiB）、近限包、单项超限包测量磁盘、主进程和渲染进程峰值内存、预览耗时、取消及界面响应。Windows 与 macOS 数据决定最终上限，超过时指出最大资源或超限项，让发送方缩小选择。首发仍为单任务单包。

## 阶段 1 · 统一范围、快照与 Markdown 导出

**代码归属**。以 `app.js` 的 `share-task`、`node-share.js` 的节点入口及 `knowledge.js` 的笔记导出入口接入。在 `node-share-model.js` 的真实树选取上补组合投影，保持子节点／下游深度独立、按原序裁剪及去重。分享选取、可读排版和包内字段提取都用显式投影。沿 `knowledge-workspace.js`、`knowledge-document.js` 核对任务主笔记、`creatorTaskId`、`knowledgeLinks`、`tabsByTask` 和临时资源页签；前三者决定默认任务归属，页签决定额外可选范围与显示顺序。既有 CSS 所有者按 `task-workspace.css`、`knowledge-workspace.css` 和 `foundation.css` 分配，复用现有 dialog 的焦点回落。

**具体实现**。从正在使用的生产编辑器捕获快照，核对 `state.shellDrafts`、简报编辑控件、节点记录缓冲、已挂载的左右笔记编辑器，以及恢复草稿和外部冲突。优先采用可见编辑状态，保留正文原样，避免为分享强制保存外部文件或关闭编辑器。本阶段实现阶段 4 中的只读资源收集规则，覆盖 Markdown ZIP 的首发资源类型。主进程收集资源只接收与所选所有者和当前快照绑定的受限请求。导出期间继续显示同一快照，刷新和取消有明确反馈。`nodeMarkdownLines()`、`exportTaskMarkdown()` 和 `task:export-document` 中已有的排版、保存框及 PDF 能力按需要复用。Markdown ZIP 写入临时文件，校验后才提交到用户选定目标，替换现有导出文件遵循原生确认。

**阶段出口**。在真实任务、节点及笔记入口演示五种范围与自定义。以打开输出文件、解压、搜索未选标记和验证相对链接作为验收。覆盖多笔记同名、折叠／筛选、未保存的两栏草稿、至少一张图片和一个普通附件、取消及错误重试。用 `tests/node-share.test.cjs`、`tests/node-share.ui.cjs`、`tests/knowledge-export.test.cjs` 做现有回归。现有节点 UI 测试中依赖「记录默认勾选」的断言改为验证新默认并显式勾选，继续保护记录内容与范围。阶段 4 复用同一资源收集逻辑验收任务包往返。

## 阶段 2 · 任务包编解码与只读预览

主进程添加任务包服务及最小 preload 接口，按操作分为导出、打开并验证、取消、提交。渲染进程提交范围或确认令牌，读取与写入由主进程负责。预览令牌绑定窗口、已验证的暂存文件和本次配置。取消、窗口销毁、超时或重新选择时作废并清理。后续提交用同一已验证快照，源文件有变化则明确提示重新读取。预览展示文本与尺寸清单，必要的正文预览走现有净化渲染。文件打开、网页访问、媒体加载和执行行为均由明确的用户操作触发。

文件校验覆盖重复路径、非普通文件、大小写和 Unicode 等价冲突、系统保留名、非法条目、异常压缩、超深结构、坏摘要、ZIP 尾部异常及未知必需能力。按固定条目命名和允许清单读取，使用应用生成的内部暂存名。除固定清单文件外，其余条目须在清单中声明并与允许的内容类型相符。使用应用现有文件路径授权和主窗口 IPC 所有权。接收端自行校验正文中的本机路径、自动加载和可执行链接，实际文件操作只允许经验证的受管资源引用或用户授权的路径。普通二进制附件通过受限预览或用户明确打开，禁止自动执行。

**阶段出口**。合法包可预览，取消和损坏包时任务数据库、恢复记录和文件目录均无持久新增。以包的实际字节核对 V1 样本，验证发包、收包、重复预览、取消、文件替换和会话结束清理。建立可读导出与包清单一致性断言，并保留错误码和界面文案映射。

## 阶段 3 · 原子追加任务与身份映射

**映射**。从当前接收方状态分配新任务／节点／文档／资源 ID，按树递归重建 `parentId`、`taskId`、子节点类型和兄弟顺序。`downstreamNodeIds` 仅映射选中且有效的端点。对历史数据中的悬挂关系在导出预览中说明并排除，校验器拒绝伪造的包内悬挂引用。内置节点状态直接对应。自定义状态优先复用同名同色定义；遇到 ID 或同名异色冲突时，新增定义用新 ID 并显示可区分的名称。`node-states.js` 现有全局上限为 24，容量不足时在确认前显示冲突，用户可释放容量或显式选状态映射；保留原状态是默认路径。新增定义和任务同一提交。若产品要求容量满时仍自动原样导入，阶段 0 改为任务内状态定义并补齐节点状态控件的作用域验证。

**接收端规则**。本地分组来自用户选择；重名允许，新任务获得本地排序。包内截止时刻用 ISO 时间保存，呈现为接收方本地时区。显式写 `deadlineReminderMinutes: null`，省略该字段会被当前规范化逻辑补成默认提醒。写入 `recurrence.frequency: none`，清除历史循环发生实例与今日／稍后标记。保留任务与节点状态和所选内容，使用独立 ID 触发本地搜索、日历、提醒和今日数据重新计算。

**写入协议**。当前 `app.js` 的 `save()`／`flushSave()` 发送整个数据库快照，`main.cjs` 的 `task-data:write` 直接写文件，`storage.cjs` 的临时文件替换只保证单文件写入。导入确认应先捕获既有编辑并成功排空常规写入，再进入短暂提交窗口。主进程使用同一写入队列及磁盘修订校验，重新读取最新数据、验证分组和状态映射，仅追加新任务及其相关记录，原子替换数据库。导入写入回执返回新 ID、插入的记录与新修订。渲染进程应用该增量，清除旧待写快照与保存指纹，恢复保存、重新计算派生状态。旧修订写入收到可重试冲突，保留它对应的用户输入并从当前状态重建待写快照。`data-maintenance.cjs` 的互斥理念可复用。导入提交与整库恢复、升级准备互斥，整库恢复仍沿用既有重启流程。

提交令牌具有一次确认语义。以本地操作 ID 和预分配任务 ID 识别已提交结果，重试时从真实持久状态取回回执。提交前可以取消。提交开始后以磁盘结果为准，界面明确显示完成或可重试失败。后续有意再次导入通过新的确认令牌创建副本。

**阶段出口**。无笔记资源的完整任务、简报和选定子树能在两套 profile 往返，任务及节点均可编辑。为并发自动保存、失败后重试、连续确认、分组变化、提醒默认值、自定义状态容量及不同完成状态增设用例。以磁盘回读确认旧任务、设置、回收站和草稿都保留，并以 `tests/data-continuity.test.cjs` 核对整库备份仍可用。

## 阶段 4 · 草稿、图片与普通附件完整往返

现有 `task-image:` 指向 `attachments.images`。`knowledge-assets.cjs` 暂存并迁移图片，`knowledge-file.cjs` 的相对资源复制也以图片为主。`knowledge-resources.cjs` 支持点击查看普通文件，未绑定草稿的相对路径不能直接复用现有打开分支。普通附件和未保存文档因此是本阶段独立交付。

**导出路径**。沿 `knowledge-core.js` 的 Markdown 链接、图片引用和源码排除范围收集，补齐首发支持的引用式链接、角括号地址、编码字符、URL 片段、文件名冲突以及适用的 wiki 嵌入。对包含引用但无法安全改写的扩展语法，在预览中列出来源并按产品规则处理。主进程只读取应用已有的受管资源、所选文档目录中经真实路径校验的文件，或原生对话框授权的单文件。简报、节点结论和记录没有笔记文件基准目录，可收集 Loop 图片及明确授权的普通附件。以解析位置从后向前改写，保持其他源文字节和换行。Markdown ZIP 和任务包共享资源解析结果，并按各自格式生成链接。

**导入和第一次保存**。生成新的笔记元数据，`filePath`、mtime、hash 和旧 Recovery ID 为空，状态为 `DRAFT`。任务主笔记落到新任务自身，附加笔记落到 `knowledgeDocuments`，同时生成本地 `knowledgeLinks`／`tabsByTask`、选中笔记和稳定链接目标。禁止由发送方或接收端同名标题自动回绑。笔记标题链接和相对笔记链接在打包时先解析为包内文档键，导入再写入新的稳定笔记 ID，保留锚点。Markdown ZIP 直接用相对文件链接。Loop 草稿另存先搬迁附件并改写资源链接，Loop 笔记之间继续使用稳定链接。

为共享导入资源设置应用受管目录，由数据库索引记录资源 ID、摘要、显示名、类型和所有者。草稿使用受管引用，主进程校验调用方和任务／笔记所有权后读取。简报与节点记录中的受管引用在各自生产渲染器复用同一个打开入口；已保存的外部 `.md` 使用正常相对附件链接。沿 `saveKnowledgeTask()` 和 `saveKnowledgeDocument()` 接入首存，沿原有安全写入机制处理附件重名、用户取消、失败清理与保存期间的新编辑。目标文件必须是新路径或用户重新明确授权的路径，已有笔记绑定保护继续生效。受管二进制用文件保存，避免将普通附件作为 Base64 写进日常全量任务 JSON。受管索引纳入新数据版本及当前规范化路径，目录纳入备份、恢复和升级复制校验。旧库读入时以空索引迁移。用现有较新数据库写入保护验证降级行为，避免旧客户端清除资源索引。

**跨文件一致性**。提交前将资源写入独立事务目录并校验，先落盘资源和事务记录，再用阶段 3 的数据库原子替换一次性引用它们。事务记录只含应用生成的本地键、预分配任务 ID 和所需摘要。数据库成功后任务内容、草稿及资源可直接恢复，外部笔记文件尚未创建。独立的 Recovery 写入可在提交后按需生成，导入正文和附件必须已由数据库及受管目录持久保护。启动先处理未完事务。数据库确有预分配 ID 且引用闭合时完成提交后的清理；数据库未引用时回收本事务文件。若状态无法确认，保留资源并报告具体问题。保留恢复中的和回收站仍引用的资源，清理范围只及应用受管目录。与 #100 共享引用核对逻辑。

**阶段出口**。在真实 Electron 完成导入→编辑→关闭→重启／恢复→首次保存取消→另存成功→独立重开。核对图片解码、附件字节摘要、相对链接、同名和锚点、草稿保护以及已有外部文件。用可控失败覆盖资源暂存、数据库替换前后和首次保存文件已写但回执失败。运行知识编辑器、资源、分屏与保存／冲突的受影响回归。

## 阶段 5 · 真机验收与集中发布

| 验收场景 | 操作与证据 |
| --- | --- |
| 范围和保密 | 五种预设及自定义。保存对照清单与包内快照。检查默认记录、下游树和未选笔记、路径、未选资源的标记 |
| 结构和内容 | 完整任务、简报、节点／子树、笔记及组合包。对比导入前后父子结构、兄弟顺序、状态、长结论、所选记录、内部引用和资源摘要 |
| 接收方连续性 | 接收端同名任务／笔记、旧草稿、设置、分组及其他未提交编辑。覆盖同次重试、主动重复导入、保存队列及重启 |
| 跨平台 | macOS 打包→Windows 导入与 Windows 打包→macOS 导入。校验中文、空格、特殊字符、时区、文件选择器、断网以及首次另存 |
